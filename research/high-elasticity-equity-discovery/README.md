# A股高弹性潜力股发现与持续跟踪

规则版本：`HEPD-V1.0`。目标目录：`research/high-elasticity-equity-discovery/`。

## 1. 定位与执行边界

本任务研究未来3—12个月内可能出现产业机会、经营拐点与市场认知变化的A股公司，持续验证证据和反证；不承诺发现“下一只妖股”、倍数收益或预测优势。产业与业绩爆发潜力是主线，连板、题材热度及换手异常仅作独立风险观察，不能代替基本面。

复用经用户确认的既有任务，保持其日程、时区、启停状态和会话归属，不新增调度或Monitor。每轮新增0—3个候选、重点复核0—5个候选，不凑数；先处理重大反证与到期评估，再做新发现。超过能力或额度的待复核事项列明积压和延后原因，不能静默遗漏。

授权写入仅限独立Notion候选库与事件库。GitHub日常只读，仅保存公开规则和空模板；规则变更须另行授权并走PR。禁止向公开仓库提交真实候选、研究结论、价格快照、私有链接及含这些内容的日志或测试夹具。不得交易、模拟交易、修改账户、发送外部消息或购买额度。

不影响`BASIC-PROD-20260825-A`、`AI-PROD-20260825-A`及其治理；不修改Champion、原FINAL/Prediction、Registry、Score或历史报告。不套用原四主指数、12段格式或生产Handoff。

## 2. 研究范围、证据与筛选

核验证券代码、交易所及公司身份，覆盖SSE、SZSE、BSE时分别披露实际范围和数据可得性。只有执行过的范围才可称已扫描，不能以少量新闻搜索冒称全市场筛选。新股、ST、停牌及流动性不足标的不得混入普通候选而不披露；高风险线索可留档，但不能因此自动升级。

候选正文至少回答：产业变化是什么；公司实际受益证据是什么；竞争壁垒和商业化障碍是什么；订单、收入、利润及现金流兑现到哪一步；当前估值与预期已计入多少；下一验证事件及否定条件是什么。亏损研发企业不因负PE机械排除，但须核验现金消耗、融资依赖、客户集中和商业化风险。价格上涨本身不证明逻辑正确。

优先交易所公告、公司原始披露、监管及统计机构材料，再用可靠数据商补充。逐条保留原文URL、发布时间、统计期、观察时刻与信息截止。事实、解释、假设分开；同公告的转载或同底层数据经多个工具返回只算一条来源。未找到证据不等于证实不存在；收入、订单及意向协议不可互换，无法核对的数值为N/A。

证据等级A表示关键事实已核验，不表示未来收益确定；B表示部分核验；C仅是线索。未经原文与时间核验的信息不得用于升级。所谓“超预期”须有同口径、发布前可得的一致预期，禁止用事后叙事补造。

## 3. 状态门禁与反证

状态依次可为：线索待核验、观察中、重点验证、降级观察、已否决、已到期。状态不是买卖指令，也不按股价涨跌自动迁移。

- 进入观察中：身份、时点及至少一项实质受益证据已核验，验证事件、期限和否定条件齐备。
- 进入重点验证：关键事实达到A，产业受益有经营或原始业务披露支撑，已检查估值、财务、治理及交易风险，并说明最强反证。关键缺口未补齐不得升级。
- 降级或否决：分别用于证据削弱/兑现延后与核心假设被推翻；重大财务异常、业务与题材不符、核心合同失效、治理或退市风险必须单列，不得被综合高分抵消。
- 已到期：120交易日观察窗口结束后的研究状态，不等于逻辑成立或失败；后续可追加证据，但不得重置旧锚点。确有重大新假设才设新研究轮次，并关联前序候选。

每次变更写明采用证据、反证、替代解释与后续验证条件。无有效增量则保持原状态，不制造新发现。

## 4. 两库与不可改写记录

候选库保存身份和首次快照；事件库追加证据、状态、评估、运行报告、验收及更正。长文本放页面正文，具体属性见[空模板](RECORD_TEMPLATES.md)。运行报告、配置验收的候选关联为空，不为系统记录造一只虚拟股票。

候选ID是研究业务键，不是平台运行ID；模板为`HEPD:<交易所>:<代码>:<首发现日期>:R<研究轮次>`，不得将占位符直接入库。首次发现、首发现信息截止、参考交易日/未复权收盘、原始理由、基准、窗口、规则版本及初始验证/否定条件锁定。状态、最近复核、下次复核和最近事件键是可更新摘要；状态事实以追加事件为准。

已否决、停牌、退市、未上涨及长期无进展样本全部保留，不删除失败样本。历史错误只通过更正事件说明，指向原事件并保留原值；不得改写首次判断以贴合后来结果。重新纳入不能冒充首次发现，新轮次需明确新假设并保留原轮次评估。

## 5. 固定评估与价格口径

首次纳入锁定一个适合其市场/规模的宽基及理由，以参考交易日D0之后第20、60、120个相应A股交易日为观察窗口。日历取对应交易所，不按个股实际成交日顺延以跳过停牌。观察跨度服务中期研究，不构成收益期限承诺。

参考收盘保存截至首次发现可用的最近正式收盘原始事实，明确未复权，不能视为成交。收盘后或周末才发现的信息不可宣称能够按该收盘价买入。窗口价格收益另用固定基期、同源且可复核的公司行为调整价格序列：`R=Q终点/Q基点−1`。分子、分母须同一基期与调整口径，绝不能用当前复权价除以主档原始价。

价格口径需说明拆股、送转、配股等除权处理；现金分红除息保留价格影响，不作现金股息再投资。若数据商的复权序列包含现金分红调整，不能直接标为本任务价格收益；无法分离或核验则N/A。现金分红总收益如有需要须另算另列，说明再投资规则、税费及来源，不与价格收益混用。

相对收益为同一窗口股票价格收益减去纳入时锁定宽基价格收益，以百分点表示，不是收益率比值。基准不得事后更换以改善结果。停牌、退市或缺数不能填0、前值填充或删样本；记录原定到期日、交易状态及缺口，收益不能计算就N/A。未经授权不模拟成交，不把观察收益称为策略收益。

评估分别记“证据/催化兑现”和“价格表现”：已兑现、未兑现、被推翻、证据不足与收益数字分开。仅对到期窗口计算；完整展示所有到期样本及缺失/积压数，不只列赢家，不将20/60/120日结果写入原预测评分体系。

## 6. 最少运行步骤与幂等

1. 读取规则、真实时间、获授权的两库及上次成功记录；核验当前任务和目标身份。
2. 先查重大风险、到期窗口和待重试，再在实际可得范围发现线索；核对原文、日期与口径。
3. 为本次执行建立明确标注的业务执行键；真实平台运行ID不可得时填空，不以业务键冒充。
4. 写前查候选ID及事件键。同键同内容跳过；同键不同内容标冲突并停止覆盖，必要时追加更正事件。重试复用原键。
5. 先保证候选存在，再追加事件，最后更新可变摘要。每一步回读属性和正文，记录成功、部分成功或失败；只有回读成功才称落库成功。
6. 追加运行报告，列新增、复核、状态变化、到期评估、积压、源缺口及落库回执。周末只处理有效增量和必要复核。

幂等键按业务事实而非重试时间确定：首次纳入以候选ID为核心；窗口评估以候选ID、锁定规则版本、窗口和原定到期日为核心；同一证据以候选ID、原文及披露版本识别；运行报告按执行键识别。更正使用新键并关联旧键，不能通过改变执行时刻绕过重复检查。

Notion的写前查询不是数据库级唯一约束，不能宣称严格并发安全。发现同键重复或并发冲突时保留记录、标待核查并停止后续同键写入，不擅自删除。部分失败按步骤和键恢复，不能把重试算新研究轮次。

同键比较的是语义载荷，不比较Notion呈现格式。重试保留原事件观察时刻和信息截止，另记本次attempt时刻及真实请求时刻，不因重试时间变化制造冲突。

内容摘要SHA256仅在可可靠复算时计算：规范化载荷版本明确、UTF-8、字段排序和空值表示固定，涵盖身份、证据、结论、状态和评估；排除Notion生成字段、格式差异、重试请求时间、写入回读回执及摘要自身。正文保留可复算载荷；不能计算时留空/null，仍须回读语义字段核对，不得伪造摘要或跳过去重。
